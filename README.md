# Diro Earthquake & Moderation Bot

기상청 지진·재난문자 알림과 Discord 서버 관리 봇입니다. Discord Gateway에 접속해 온라인 상태를 유지하고, 슬래시 명령어·메시지 삭제/수정·새 서버 감사 로그를 처리합니다.

## Render와 Discord 설정

1. Discord Developer Portal → 애플리케이션 → **Bot → Privileged Gateway Intents → Message Content Intent**를 켭니다. 이 코드에는 Server Members Intent가 필요하지 않습니다. 승인 대상 봇은 Discord의 승인이 필요할 수 있습니다.
2. OAuth2 초대 범위에 **bot**, **applications.commands**를 포함해 서버에 초대합니다. 봇에는 채널 보기, 메시지 보내기, 링크 임베드, 메시지 기록 보기, 감사 로그 보기, 멤버 차단, 멤버 타임아웃 권한을 부여합니다. 관리자(Administrator) 권한은 필요하지 않습니다.
3. 서버 역할 목록에서 **봇 역할을 관리할 멤버의 역할보다 위**에 둡니다. 명령어 실행자도 대상보다 높은 역할과 해당 관리 권한이 필요합니다.
4. Render 환경변수에 아래 값을 설정합니다. 토큰과 API 키는 환경 설정에서만 입력하며 저장소·채팅·로그에 넣지 마세요.
5. 변경 코드를 Render가 배포하는 브랜치에 반영하고 재배포합니다. Runtime **Node.js 20 이상**, Root Directory **저장소 루트**, Build Command **`npm ci`**, Start Command **`npm start`**, Health Check Path **`/health`**입니다. 기존 `quake-bot` 진입점도 지원합니다.

| 변수 | 용도 |
| --- | --- |
| `DISCORD_TOKEN` | 필수: Bot 페이지의 봇 토큰 |
| `CHANNEL_ID` | 필수: 지진·재난문자 알림 채널 ID. `CHANNEL_IDS` 첫 항목도 지원 |
| `LOGS` | 삭제·수정·감사·관리 로그 채널 ID. `LOG_CHANNEL_ID`도 지원 |
| `KMA_KEY` | 지진 조회용 공공데이터포털 기상청 지진정보 서비스 인증키 |
| `SAFETY_KEY` | 재난안전데이터공유플랫폼 긴급재난문자 인증키 |
| `GUILD_ID` | 선택: 서버 ID. 지정하면 `CHANNEL_ID`의 서버와 같은지 확인 |
| `DATA_DIR` | 기록 저장 전용 디렉터리. 기본 `.data`. 운영에서는 영구 디스크 경로 지정 |
| `ALERT_MENTION_EVERYONE` | 기본 `false`. `true`일 때만 알림의 `@everyone` 멘션 허용 |
| `PORT` | Render가 지정하는 웹 서버 포트. 기본 `3000` |
| `TRUST_PROXY` | 기본 `false`. 신뢰할 수 있는 프록시가 전달 헤더를 덮어쓸 때만 `true` |

`CHANNEL_ID`와 `LOGS`는 같은 서버의 텍스트 채널이어야 합니다. 봇이 여러 서버에 설치되어 있어도 명령어와 로그는 알림 채널의 서버에만 적용됩니다. 인증키가 없는 소스는 비활성화하고 다른 기능은 계속 실행합니다. `.env.example`은 변수 목록이며, 프로그램은 `.env` 파일을 자동으로 읽지 않습니다.

**경고·타임벤 예약 보존:** Render 영구 디스크를 예를 들어 `/var/data`에 마운트하고 `DATA_DIR=/var/data/diro`로 지정합니다. 이 디렉터리는 봇 전용으로 사용하고 접근 권한은 디렉터리 `0700`, 파일 `0600`으로 제한합니다. 영구 디스크가 없으면 재배포 때 기록과 해제 예약이 사라질 수 있습니다. **한 저장 디렉터리에는 봇 인스턴스 하나만 실행하세요.** 여러 프로세스의 공유 파일 쓰기는 지원하지 않습니다.

봇이 24시간 작동하려면 Render 인스턴스가 계속 실행되어야 합니다. 서비스가 휴면·중단되면 온라인 상태와 알림 조회도 중단됩니다. 클라우드 개발 환경은 24시간 운영 서버를 대신하지 않습니다.

## 명령어

로그인 후 해당 서버에 영어 명령어를 자동 등록하고 이전 한국어 슬래시 명령어를 정리합니다. `/`를 입력해 명령어를 선택한 뒤 `user` 항목에 숫자 사용자 ID를 입력하세요. `minutes`는 정수로 지정하는 분 단위 기간이며 `reason`은 선택 사항입니다.

| 예시 | 동작 | 실행자·봇 권한 |
| --- | --- | --- |
| `/warn user:123456789012345678 reason:도배` | 서버별 경고 기록과 관리 로그 저장 | 멤버 타임아웃(Moderate Members) |
| `/warnings user:123456789012345678` | 누적 경고와 최근 5개 확인 | 멤버 타임아웃 |
| `/timeban user:123456789012345678 minutes:60 reason:반복 위반` | 60분 차단 후 자동 해제. 최대 365일 | 멤버 차단(Ban Members) |
| `/permban user:123456789012345678 reason:중대한 위반` | 기간 없는 서버 차단 | 멤버 차단 |
| `/mute user:123456789012345678 minutes:10` | Discord 타임아웃. 최대 28일 | 멤버 타임아웃 |
| `/unmute user:123456789012345678` | 타임아웃 해제 | 멤버 타임아웃 |
| `/unban user:123456789012345678` | 차단 해제 | 멤버 차단 |
| `/status` | Gateway, 명령어, 로그, API·알림 전송 상태 확인 | 실행자 멤버 타임아웃 |

응답은 실행자에게만 표시합니다. 본인·봇·서버 소유자·관리자·같거나 높은 역할은 관리 대상으로 지정할 수 없습니다. 경고와 뮤트는 서버 멤버에게 적용하며, 경고는 기록 방식입니다. 대상에게 DM을 보내지는 않습니다.

타임벤은 Discord 요청 전에 고유 표식을 포함한 해제 예약을 파일에 저장합니다. 재시작 후에도 복구하며, 30초마다 만료를 확인합니다. 봇이 꺼져 있으면 해제는 다시 켜진 뒤 처리합니다. 현재 차단 사유의 표식이 일치하는 경우만 해제하므로 나중에 다른 관리자가 만든 영구 차단을 자동으로 풀지 않습니다. 기존 차단을 타임벤으로 덮어쓰지 않습니다.

## 관리 로그

`LOGS` 채널에는 다음 내용이 올라옵니다.

- 메시지 삭제: 작성자·채널·메시지 ID·삭제된 원문·첨부파일 메타데이터
- 메시지 수정: 수정 전 원문과 변경 후 내용
- 일괄 삭제: 보관된 각 원문을 묶어서 기록
- 새 서버 감사 로그: 실행자·작업·대상·사유·변경 사항
- 관리 명령어 결과와 타임벤 자동 해제
- 반복을 제한한 API/알림 전송 오류

평상시 `fetched` 조회 결과는 Render 콘솔에만 기록합니다. 감사 로그는 Gateway에서 새로 발생한 항목을 전달하며 과거 기록 전체를 가져오지는 않습니다. 봇 자신의 감사 항목은 중복을 줄이기 위해 제외하고 관리 명령어 결과를 별도로 기록합니다. 메시지 삭제 실행자는 별도의 감사 항목으로 표시하며, 시간상 가까운 감사 기록만으로 특정 메시지의 삭제자를 추정하지 않습니다.

**원문 보관 제한:** 봇이 온라인일 때 관찰한 메시지 최대 5,000개를 최대 6시간 동안 메모리에 보관합니다. 재시작·오프라인·보관 기간 만료·크기 제한 때문에 원문이 없으면 “원문 확인 불가”라고 표시합니다. 삭제된 메시지는 Discord API로 복구할 수 없습니다. 메시지 원문과 첨부파일은 디스크에 저장하지 않지만, 로그 채널에 전송된 원문은 Discord에 남으므로 해당 채널의 열람 권한과 보관 정책을 설정하세요. 첨부파일은 다운로드하지 않습니다.

로그와 명령어 응답은 멘션을 차단하고 비밀값을 마스킹합니다. 로그 채널·다른 서버·DM·봇 메시지는 내용 로그에서 제외합니다. 로그 전송 대기 건수는 100개로 제한하며, 폭주로 생략한 건수는 `/health`의 `discordConnection.droppedLogs`에 표시합니다.

## 지진·재난문자와 진단

- 1분마다 어제부터 오늘(KST)까지의 통보를 조회합니다. Safety의 `crtDt`는 [공식 명세](https://www.safetydata.go.kr/disaster-data/apiDataTable?dataSn=228)의 조회시작일자입니다.
- 조회 결과는 100개씩 페이지를 순회하며 최대 20페이지로 제한합니다. 제한에 도달하면 정상 조회로 숨기지 않고 오류로 표시합니다.
- 지진은 최근 30분 내 발표된 통보를 처리해 발생 시각보다 늦은 발표도 수신합니다.
- 재난문자는 첫 실행에 최근 5분만 전송하고 이후 최근 30분의 미전송 문자를 처리합니다.
- 한 알림의 전송 실패가 다른 알림을 막지 않으며 실패한 알림은 다음 조회에서 다시 시도합니다.
- 전송 성공 이후에만 중복 방지 기록을 저장합니다. 영구 디스크가 있으면 재시작에도 기록이 유지됩니다. 전송 직후 기록 저장 전에 프로세스가 종료되면 중복 전송될 수 있습니다.
- API의 JSON/XML 오류, 인증키 문제, 비정상 응답을 빈 결과로 간주하지 않습니다.

`/health`의 `status: ok`는 웹 서버 응답만 의미합니다. 다음을 따로 확인하세요.

| 항목 | 정상 확인 |
| --- | --- |
| `discordConnection.gateway` | `ready`이면 Gateway 연결. `error`이면 토큰과 Message Content Intent 확인 |
| `discordConnection.commands` | `ok`이면 명령어 등록. 오류 시 초대 범위·서버·채널 권한 확인 |
| `discordConnection.logs`, `audit` | 로그 채널 전송과 감사 로그 보기 권한 확인 |
| `kma`, `safety` | `ok: fetched=..., sent=...`. `disabled`면 키 없음, `error`면 서버 로그 또는 `/status` 확인 |
| `discord` | 알림 채널의 마지막 전송 결과. `idle`은 아직 알림을 보내지 않은 상태 |
| `lastCheckAt` | 최근 조회 시각 |

공개 상태 응답에는 상세 오류 본문이나 자격증명을 제공하지 않습니다. `/status`는 권한 있는 관리자만 확인할 수 있습니다. HTTP 입력 파싱·요청 빈도·메모리·API 응답 크기를 제한하고, 패키지 버전과 lockfile을 고정합니다.

Safety API의 `UNREGISTERED IP ERROR`는 공급자의 접속 IP 검사 문제입니다. Render 서비스 → **Connect → Outbound**의 실제 공인 IP 목록/대역을 Safety 이용신청의 허용 IP에 등록하세요. IP 제한을 없애거나 인증 검증을 끄는 방법으로 우회하지 않습니다. 등록 후 다음 조회에서 재시도합니다.

참고: [기상청 API](https://apihub.kma.go.kr/apiList.do?seqApi=7), [긴급재난문자 API](https://www.safetydata.go.kr/disaster-data/view?dataSn=228), [Render 외부 통신 IP](https://render.com/docs/outbound-ip-addresses).

## 로컬 검증

```bash
npm ci
npm test
```

테스트는 외부 API·실제 Discord 전송 없이 실행합니다. 권한·역할 검사, 원문 캐시·부분 메시지·감사 로그, 타임벤 복구, 실제 파일 저장 실패, 지진 재시도·페이지 처리, HTTP 서버 시작/재시작과 보안을 검증합니다. Gateway 이벤트·API 전송은 모의 구현이며, 실제 토큰·서비스를 이용한 운영 검증은 별도로 필요합니다.
